# bs-translator: 전시회 부스용 푸시투토크 통역 웹앱

## 1. 개요

시끄러운 전시회 부스에서 한국 영업 담당자와 외국인 방문객(영어, 일본어, 중국어)이 휴대폰 하나로 대화하도록 돕는 통역 앱입니다. 안드로이드 크롬 세로 화면 전용입니다.

- 방문객이 오면 `번역 시작하기`, 떠나면 `번역 중지`를 누릅니다. 그 사이에만 OpenAI와 연결되고 요금이 발생합니다. 앱을 열어만 둔 동안에는 연결이 없습니다.
- 말할 사람이 자기 버튼을 한 번 누르면 녹음이 시작되고, 다시 누르면 끝납니다.
- 중지하면 녹음 중에 받아 둔 번역 음성이 곧바로 스피커로 재생되고, 뒤따라 오는 나머지 음성도 이어서 재생됩니다. 번역 자막은 받는 즉시 화면에 표시됩니다.
- 버튼을 누르지 않은 동안에는 마이크 소리를 보내지 않습니다. 녹음 중에는 번역 음성을 재생하지 않습니다(에코 방지).

### 구조

```
[안드로이드 크롬] --(WebRTC, 음성/자막)--> api.openai.com (기본 GPT-Live-1, 선택 gpt-realtime-translate)
        |
        +--(HTTPS, PIN + 세션 요청)--> [Cloudflare Worker worker/ + Durable Object]  --(API 키)--> api.openai.com
```

- 음성은 폰 브라우저와 OpenAI 사이를 WebRTC로 직접 오갑니다. 서버를 거치지 않습니다.
- 서버는 Cloudflare Worker(`worker/`)입니다. PIN을 확인한 뒤 OpenAI 세션을 대신 열어 줍니다.
  - GPT-Live-1: SDP를 중계합니다(`/api/live/session`).
  - gpt-realtime-translate: 수명이 짧은 client secret `ek_...`를 발급합니다(`/api/session`).
- 빌드된 웹앱(`web/dist`)은 Workers 정적 자산으로 같은 주소에서 제공됩니다.
- 듀얼 모드(9절, 마스터/게스트)의 상태는 **Durable Object 하나**가 맡습니다. 이 객체가 두 폰 사이의 번역 텍스트를 SSE(`/api/dual/events`)로 전달하고, 게스트 PIN 보관과 접속 요청/수락도 처리합니다. 게스트는 연결된 동안에만 서버가 발급한 토큰으로 엔진 세션을 열 수 있습니다. 음성은 이때도 서버를 거치지 않습니다.
- OpenAI API 키와 `APP_PIN`은 Cloudflare의 비밀값(Secrets)에만 있습니다. 웹 코드와 빌드 결과물에는 들어가지 않습니다.
- 로그와 대화 기록은 파일로 저장하지 않습니다. 오류와 OpenAI 세션 생성만 Cloudflare 대시보드의 **Workers Logs**(콘솔 로그)에 남습니다. 과금 확인용입니다.
- API 조사 내용과 근거는 [docs/api-notes.md](docs/api-notes.md)에 있습니다.

## 2. 요구사항

- Node.js 22 이상, npm
- Cloudflare 계정 (Workers, Durable Objects 사용)
- OpenAI API 키
- 폰에서 마이크를 쓰려면 **HTTPS가 필수**입니다. Cloudflare에 배포하면 `https://<이름>.<계정>.workers.dev` 또는 연결한 도메인으로 HTTPS가 자동으로 붙습니다.

## 3. 설치 (로컬 개발용)

저장소 루트에서 실행합니다.

```bash
npm install
cp .dev.vars.example .dev.vars
```

`.dev.vars`를 열어 두 값을 채웁니다. 이 파일은 로컬 `wrangler dev` 전용이며 커밋하지 않습니다(`.gitignore`에 들어 있음).

| 변수 | 의미 |
|---|---|
| `OPENAI_API_KEY` | OpenAI API 키. Worker에서만 씁니다. 비어 있으면 실제 번역은 안 되고 503이 돌아옵니다(모의 모드는 동작). |
| `APP_PIN` | 마스터(앱) 입장 PIN, 숫자 4~6자리. 비어 있거나 형식이 틀리면 API가 503 `server_not_configured`를 돌려줍니다. |

`wrangler.jsonc`의 `vars.CLIENT_SECRET_TTL_SECONDS`(기본 600초, 10~7200)는 gpt-realtime-translate용 단기 토큰의 수명입니다.

## 4. 로컬 실행

```bash
npm run build   # 웹앱을 web/dist로 빌드
npm run dev     # wrangler dev: Worker + Durable Object + 웹앱을 http://localhost:8790 에서 제공
```

`wrangler dev`는 Cloudflare와 같은 런타임(workerd)을 로컬에서 돌립니다. 듀얼 모드의 게스트 PIN은 로컬 Durable Object 저장소(`.wrangler/state`)에 남습니다. 상태 확인은 `http://localhost:8790/health`입니다.

웹 화면을 고치면서 바로 보고 싶으면 터미널을 하나 더 열어 `npm run dev -w web`(Vite, 기본 http://localhost:5173)을 띄웁니다. Vite가 `/api`와 `/health`를 `http://localhost:8790`으로 넘겨 줍니다.

### 모의 모드와 데모 화면

- **모의 모드** `?mock=1`: OpenAI에 연결하지 않고 가짜 번역 엔진으로 동작합니다. API 키 없이 UI와 녹음/재생 흐름을 시험할 때 씁니다. 서버는 켜 있어야 하고 PIN 입력도 필요합니다(게스트 화면 `/guest?mock=1`은 PIN 없이). 화면에 `MOCK` 표시가 붙습니다.
  예: `http://localhost:8790/?mock=1`
- **데모 화면** `?demo=1`: 샘플 대화로 모든 화면 상태를 보여 주는 디자인 확인용 페이지입니다. 오른쪽 끝의 `DEMO` 손잡이로 모드, 언어, 테마, 배너 등을 바꿀 수 있습니다. 데모 PIN은 `1234`입니다.

## 5. 빌드 보안 점검

배포 전에 빌드 결과물에 API 키가 섞이지 않았는지 확인합니다.

```bash
npm run build
npm run check:secrets
```

`check-secrets: OK (N files scanned)`가 나와야 합니다. 이 점검은 `web/dist` 전체에서 `.dev.vars`(또는 `.env.local`)의 키 값, `sk-...` 형태의 문자열, `OPENAI_API_KEY`라는 글자를 찾습니다.

## 6. Cloudflare 배포 (GitHub 연동)

GitHub 저장소를 Cloudflare **Workers Builds**에 연결하면, `main`에 푸시할 때마다 자동으로 빌드하고 배포합니다.

1. Cloudflare 대시보드 -> **Workers & Pages** -> **Create** -> **Import a repository**(Git 연결)에서 GitHub의 `hyunia69/bs-translate`를 고릅니다.
2. 빌드 설정:

   | 항목 | 값 |
   |---|---|
   | Project name | `bs-translate` (`wrangler.jsonc`의 `name`과 같아야 함) |
   | Production branch | `main` |
   | Root directory | `/` (저장소 루트) |
   | Build command | `npm run build` |
   | Deploy command | `npx wrangler deploy` |

3. 첫 배포가 끝나면 Worker 설정 -> **Variables and Secrets**에서 두 비밀값을 **Secret** 형식으로 추가합니다.
   - `OPENAI_API_KEY`
   - `APP_PIN` (4~6자리 숫자)

   터미널에서는 `npx wrangler secret put OPENAI_API_KEY`, `npx wrangler secret put APP_PIN`으로도 넣을 수 있습니다. 비밀값은 저장 즉시 적용되며 다시 배포할 필요가 없습니다.
4. Durable Object(듀얼 모드 허브)는 `wrangler.jsonc`의 설정과 마이그레이션으로 첫 배포 때 자동으로 만들어집니다. 따로 만들 것은 없습니다.
5. 배포 주소 `https://bs-translate.<계정>.workers.dev`를 엽니다. 도메인을 쓰려면 Worker 설정 -> **Domains & Routes**에서 Custom Domain을 추가하세요.
6. 게스트용 QR 코드는 `https://<배포 주소>/guest`로 만듭니다.

확인:
- `https://<배포 주소>/health`가 `{"ok":true,"openaiConfigured":true}`이면 비밀값까지 정상입니다.
- 오류와 OpenAI 세션 생성 기록은 Worker -> **Logs**(Workers Logs)에서 봅니다.

### 부스 네트워크 조건

음성은 폰이 `api.openai.com`과 직접 주고받습니다. 그래서 **폰이 붙는 부스 Wi-Fi(또는 모바일 데이터)에서 `api.openai.com`으로 나가는 HTTPS와 WebRTC(UDP)가 막혀 있지 않아야** 합니다. 전시장 Wi-Fi가 UDP를 막는 경우가 있으니 행사 전에 현장 망에서 꼭 시험하세요. 안 되면 폰의 모바일 데이터나 테더링을 쓰세요.

## 7. 안드로이드 폰 접속

1. 크롬에서 `https://<도메인>`을 엽니다.
2. PIN(Cloudflare 비밀값 `APP_PIN`)을 입력하고 `입장`을 누릅니다.
3. 방문객이 오면 `번역 시작하기`를 누릅니다. 머리글의 점이 초록이 되면 말하기 버튼을 쓸 수 있습니다.
4. 처음 말하기 버튼을 누를 때 마이크 권한을 묻습니다. **허용**을 누릅니다.
5. 크롬 메뉴(⋮) -> `홈 화면에 추가` 또는 `앱 설치`를 누릅니다. 홈 화면 아이콘으로 열면 주소창 없이 세로 전체 화면으로 뜹니다.

현장 권장 사항:

- 외장 마이크(USB-C 또는 블루투스)를 쓰세요. 꽂은 뒤 설정(톱니바퀴) -> 마이크 목록에서 그 마이크를 고릅니다. 시끄러운 부스에서는 내장 마이크보다 훨씬 잘 알아듣습니다.
- 앱이 열려 있는 동안 화면이 꺼지지 않도록 잡아 둡니다(Wake Lock). 그만큼 배터리를 쓰니 폰은 충전기에 연결해 두세요.

## 8. 실제 폰 테스트 방법

### 원격 디버깅 (크롬 DevTools)

1. 폰: 설정 -> 휴대전화 정보 -> 빌드 번호 7번 탭으로 개발자 옵션을 켜고, 개발자 옵션 -> `USB 디버깅`을 켭니다.
2. 폰을 USB로 PC에 연결하고 폰에 뜨는 디버깅 허용 창을 승인합니다.
3. PC 크롬에서 `chrome://inspect`를 열면 폰의 탭이 보입니다. `inspect`를 누르면 콘솔과 네트워크를 볼 수 있습니다.

### 로컬 서버로 폰에서 시험할 때

폰에서 `http://192.168.x.x:8790`처럼 HTTP로 열면 HTTPS가 아니어서 마이크가 동작하지 않습니다. 방법은 둘입니다.

- 배포한 Cloudflare 주소(HTTPS)로 시험합니다(가장 확실함).
- USB 디버깅이 연결된 상태라면 `chrome://inspect`의 `Port forwarding`에 `8790` -> `localhost:8790`을 추가한 뒤, 폰 크롬에서 `http://localhost:8790`을 엽니다. `localhost`는 크롬이 안전한 주소로 취급하므로 마이크가 동작합니다.

### "누르지 않은 동안 음성을 보내지 않는지" 확인

- 폰 크롬 또는 원격 디버깅 중인 PC 크롬에서 `chrome://webrtc-internals`를 엽니다. 해당 연결의 `outbound-rtp` (audio) 항목에서 `bytesSent` 그래프를 봅니다. 버튼을 누른 구간에만 오르고, 턴과 턴 사이에는 평평해야 정상입니다.
- 원격 디버깅 콘솔에서 턴을 시작할 때마다 `[engine] pre-turn audio bytesSent=0` 줄이 찍힙니다. 녹음 전에 보낸 음성이 0바이트라는 뜻입니다.

## 9. 사용법

- **번역 시작하기 / 번역 중지**: 앱을 열면 말하기 버튼 대신 큰 `번역 시작하기` 버튼 하나가 보입니다. 방문객이 오면 이 버튼을 눌러 통역 엔진에 연결합니다(1~2초 걸리며, 머리글의 점이 노랑에서 초록으로 바뀌면 준비된 것입니다). 연결되면 머리글 바로 아래에 `● 번역 중 · 엔진 이름 · 경과 시간` 띠와 `번역 중지` 버튼이 나타나고, 말하기 버튼 두 개가 생깁니다. 방문객이 떠나면 `번역 중지`를 누르세요. 녹음 중이던 턴은 그 자리에서 끝나고 OpenAI와의 연결이 모두 닫히며 재생도 멈춥니다. **이유는 비용입니다.** 기본 엔진 GPT-Live-1은 연결되어 있는 시간 전체(아무도 말하지 않는 동안 포함)에 분당 $0.05가 청구되므로, 연결은 대화하는 동안에만 유지해야 합니다. 앱을 다시 열면 항상 중지 상태로 시작하고, 탭을 닫을 때도 연결을 닫습니다.
- **말하기 버튼 두 개**: 아래쪽 `🇰🇷 한국어` 버튼은 영업 담당자용, 상대 언어 버튼은 방문객용입니다. 한 번 누르면 녹음 시작, 다시 누르면 중지입니다(누르고 있을 필요 없음). 한쪽이 녹음 중이면 다른 쪽 버튼은 잠깁니다.
- **녹음 중 표시**: 화면 전체에 빨간 테두리, 버튼에 경과 시간과 입력 레벨이 나옵니다. 한 턴은 **최대 60초**이고, 10초 남으면 카운트다운이 뜨며 60초가 되면 자동으로 멈춥니다.
- **상대 언어**: 위쪽 머리글의 `EN | 日本語 | 中文`에서 고릅니다. 녹음 중에는 바꿀 수 없습니다. 번역 중에 바꾸면 새 언어 방향으로 다시 연결하고, 중지 상태에서는 설정만 바뀝니다.
- **연결 상태 점**: 회색은 중지 상태(연결 없음), 초록은 준비됨, 노랑은 연결 중 또는 재연결 중입니다. 연결 중에는 말하기 버튼이 흐리게 보이고 눌리지 않습니다.
- **대면 모드**: 머리글의 `대면` 버튼으로 한손 모드와 대면 모드를 오갑니다. 대면 모드는 폰을 테이블에 눕혀 두고 마주 앉을 때 씁니다. 위쪽 절반이 180도 돌아가 방문객 쪽을 향합니다. 중지 상태에서는 방문객 쪽 절반에 말하기 버튼 대신 상대 언어로 "잠시만 기다려 주세요"가 보입니다.
- **다시 듣기**: 스피커 아이콘이 있는 말풍선을 탭하면 번역 음성을 다시 재생합니다. 재생 중인 말풍선을 다시 탭하면 멈춥니다. 녹음 중에는 재생하지 않습니다.
- **설정(톱니바퀴)**:
  - 마이크: 사용할 입력 장치 선택
  - 번역 엔진: `GPT-Live-1 (기본)` 또는 `gpt-realtime-translate`. 10절 참고. 번역 중에 바꾸면 연결을 새로 만들고, 중지 상태에서는 설정만 저장됩니다.
  - 글자 크기: 3단계
  - 테마: 고대비 / 다크
  - 대화 기록 지우기: 확인 후 폰에 저장된 대화를 모두 지웁니다.
  - (듀얼 마스터일 때) 사용 모드, 게스트 PIN 변경

기본 모드의 대화 기록(텍스트만)은 그 폰의 브라우저에만 저장되어 앱을 다시 열어도 남아 있습니다. 서버에는 저장하지 않습니다. 번역 음성은 저장하지 않으므로 앱을 다시 열면 이전 말풍선은 다시 듣기가 안 됩니다.

### 듀얼 모드 (마스터 / 게스트)

전시회 부스용입니다. 부스 담당자의 폰이 **마스터**, 방문객의 폰이 **게스트**입니다. 각 폰은 자기 말을 상대 언어로 번역하고, 그 텍스트를 서버를 거쳐 상대 폰에 보냅니다. 위의 한 폰짜리 사용법(기본 모드)은 그대로입니다. 서버 API와 이벤트 형식은 [docs/dual-protocol.md](docs/dual-protocol.md)에 있습니다.

**마스터 (부스 담당자)**

1. 평소처럼 PIN(`APP_PIN`)으로 입장한 뒤 설정(톱니바퀴) -> `사용 모드`에서 `듀얼 (마스터)`를 고릅니다.
2. 내 언어를 고르고 대기를 시작합니다. 대기 화면에 **게스트 PIN**(4자리)과 게스트 접속 주소(`https://<도메인>/guest`)가 보입니다. 이 주소를 QR 코드로 만들어 부스에 붙여 두세요.
3. 게스트가 요청하면 대기 화면에 `게스트 123 · English`처럼 요청이 뜹니다. `수락`을 누르면 연결되고 양쪽 폰이 통역 엔진에 자동으로 연결됩니다. `거절`하면 게스트 화면에 거절 안내가 뜹니다.
4. 대화: 아래쪽 키 하나(`한국어 시작`)를 눌러 말하고 다시 눌러 끝냅니다. 번역은 게스트 폰에 글자로 뜹니다. 게스트가 말한 내용은 한국어 번역으로 내 화면에 뜹니다.
5. **종료**: 머리글의 `종료`를 누르면 게스트 연결도 끊기고, 두 폰의 통역 엔진 연결이 모두 닫힙니다. 서버는 그 게스트가 엔진 세션을 새로 여는 것도 거부합니다. 마스터는 다시 대기 화면으로 돌아가 다음 게스트를 기다립니다.
6. **게스트 PIN 변경**: 설정 -> `게스트 PIN`에 새 4자리를 넣고 `변경`을 누릅니다. 바꾸고 싶을 때만 바꾸면 되고, Cloudflare Durable Object 저장소에 저장되어 재배포해도 유지됩니다. 새로 접속하는 게스트에게는 바뀐 PIN이 보입니다.

**게스트 (방문객)**

1. 부스의 QR 코드를 찍으면 `/guest` 화면이 바로 열립니다. 앱 PIN, 설정, 기본 모드는 보이지 않습니다.
2. 자기 언어를 고르면(처음에는 English가 선택되어 있음) 화면에 "PIN 코드 **1234**를 입력하세요"가 그 언어로 나옵니다. 보이는 숫자를 입력하고 요청을 누릅니다.
3. 마스터가 수락하면 대화 화면으로 바뀝니다. 수락 전에는 대기 화면이고 `취소`할 수 있습니다.
4. 마스터가 종료하면 "대화가 종료되었습니다" 안내(게스트 언어)와 함께 처음 화면으로 돌아갑니다.

규칙:

- 마스터는 한 대만 있습니다. 다른 폰이 마스터로 대기를 시작하면 이전 마스터는 밀려납니다.
- 게스트는 마스터와 다른 언어만 고를 수 있습니다. 마스터가 대기 중이 아니면 요청은 "준비되지 않았습니다"로 거절됩니다.
- 마스터가 다른 게스트와 통역 중일 때 들어온 요청은 대기 목록에 남았다가, 종료 후에 수락할 수 있습니다.
- 페이지를 닫으면 연결은 곧바로 풀립니다. 네트워크가 끊긴 경우에는 약 20초 동안 다시 붙기를 기다린 뒤 풉니다. 마스터가 나가면 모든 게스트 연결과 요청이 종료됩니다.
- 게스트 PIN은 게스트 화면에 그대로 보이는 확인용 숫자입니다. 실제 접속 허가는 마스터의 `수락`입니다.
- 듀얼 상태(대기, 요청, 연결)는 Durable Object의 메모리에만 있으므로 재배포하거나 모두가 오래 접속을 끊으면 다시 대기를 시작해야 합니다. 게스트 PIN만 Durable Object 저장소에 유지됩니다.
- 듀얼 대화 내용은 어디에도 저장하지 않습니다(서버는 중계만 함).
- 게스트 폰의 마이크도 **HTTPS 주소**에서만 동작합니다(2절). QR 주소는 반드시 `https://`여야 합니다.

**비용**: 연결되어 있는 동안 각 폰은 엔진 방향을 **하나만**(내 언어 -> 상대 언어) 열어 둡니다. GPT-Live-1 기준으로 폰 한 대에 분당 약 $0.05, 두 폰을 합치면 분당 약 $0.10입니다. 아무도 말하지 않아도 연결 시간만큼 과금되므로(10절) 대화가 끝나면 `종료`를 누르세요. 마스터 대기 중과 게스트 요청 중에는 엔진 연결이 없습니다. 과금 누수 조사 내용은 [docs/billing-notes.md](docs/billing-notes.md)에 있습니다.

## 10. GPT-Live-1 엔진 (기본)

`gpt-live-1` 모델을 쓰는 GPT-Live-1이 **기본 엔진**입니다. OpenAI와의 연결은 `번역 시작하기`를 누른 뒤부터 `번역 중지`를 누를 때까지만 존재합니다. 중지 상태에서는 세션도, 과금도 없습니다. 공식 문서로 확인되지 않은 부분이 있으니(13절) 행사 전에 현장에서 시험하고, 비교용으로는 설정에서 `gpt-realtime-translate` 엔진을 고를 수 있습니다.

### 전환 방법

설정(톱니바퀴) -> `번역 엔진`에서 `GPT-Live-1 (기본)`과 `gpt-realtime-translate` 중 하나를 고릅니다. 번역 중에 바꾸면 기존 연결을 닫고 새 엔진으로 다시 연결하며, 중지 상태에서는 설정만 바뀝니다. 버튼, 언어 선택, 다시 듣기 같은 사용법은 두 엔진이 같습니다.

### gpt-realtime-translate와 다른 점

- **연결 방식**: Live에는 브라우저용 단기 토큰이 문서화되어 있지 않습니다. 그래서 폰은 SDP offer만 우리 서버(`/api/live/session`)로 보내고, 서버가 API 키로 OpenAI의 `POST /v1/live/sessions`를 호출해 answer를 돌려줍니다. API 키는 여전히 서버에만 있습니다. 음성 자체는 gpt-realtime-translate처럼 폰과 `api.openai.com` 사이를 WebRTC로 직접 오가므로 6절의 부스 네트워크 조건이 똑같이 적용됩니다.
- **세션 재사용**: 번역 중에는 언어 방향마다(예: 한국어 -> 영어, 영어 -> 한국어) 세션을 하나씩 열어 두고 여러 턴에 걸쳐 다시 씁니다. 버튼을 누르면 `session.input_audio.unmute`를 보내고 마이크를 붙이며, 다시 누르면 마이크를 떼고 `session.input_audio.mute`를 보냅니다. `번역 중지`를 누르면 두 세션을 모두 닫습니다. gpt-realtime-translate는 턴마다 세션을 닫고 예비 세션으로 갈아탑니다.
- **턴 종료 판단**: Live에는 "번역이 끝났다"를 알리는 이벤트가 문서에 없습니다. 그래서 중지 뒤 번역 자막과 음성이 1.5초 동안 들어오지 않으면 턴을 끝냅니다. 중지 뒤 아무 출력도 오지 않으면 2.5초 뒤에 끝내고, 12초가 지나도 계속 출력이 오면 `timeout`으로 끝냅니다.
- **용어집 적용**: Live는 공식 문서의 `instructions` 필드를 받습니다. 서버가 공식 번역 프롬프트 뒤에 `glossary.json`의 용어를 `원문 용어 => 번역 용어` 줄로 붙여 보냅니다(11절).
- **세션 갱신**: 세션 만료(`session.started`의 `expires_at`) 60초 전에, 진행 중인 턴이 없을 때 새 세션으로 바꿉니다. 연결이 끊기면 gpt-realtime-translate와 같은 1, 2, 4, 8, 15초 간격으로 다시 연결합니다(번역 중일 때만).
- **송신 확인**: 원격 디버깅 콘솔에 턴마다 `[engine:live] pre-turn audio bytesSent=0` 줄이 찍힙니다. 8절의 확인 방법과 같은 뜻입니다.

### 비용

모델 페이지 기준으로 Live 음성 세션은 분당 $0.05이고 **연결되어 있는 동안의 세션 시간**을 초 단위로 청구합니다. 여기에 WebRTC 세션을 만들 때 초기화 비용으로 15초 분량이 청구되며, 세션이 시작되면 그만큼 상계됩니다([docs/api-notes.md](docs/api-notes.md) 5.9절). gpt-realtime-translate는 오디오 시간 기준 분당 $0.034입니다.

그래서 앱은 연결을 `번역 시작하기`와 `번역 중지` 사이에만 유지합니다. 번역 중에는 **아무도 말하지 않아도** 방향 2개(한국어 -> 상대 언어, 상대 언어 -> 한국어)가 각각 과금되므로 번역 중 1분당 약 2 x $0.05 = $0.10입니다. 예를 들어 방문객 한 명과 5분씩 하루 20명을 상대하면 20 x 5분 x $0.10 = 약 $10이고, 중지 상태로 열어 둔 시간은 요금이 없습니다. 반대로 중지를 잊고 8시간 내내 번역 중으로 두면 2 x 480분 x $0.05 = $48이 됩니다. 대화가 끝나면 `번역 중지`를 누르는 습관이 비용을 결정합니다. 탭을 닫아도 연결은 닫히지만, 앱을 뒤로 돌려 둔 채 화면만 끄면 연결은 유지되니 꼭 중지를 누르세요.

### 엔진 비교 방법

같은 문장을 두 엔진으로 번갈아 말해 보고 체감 속도와 번역 품질을 비교하세요. 원격 디버깅 콘솔(8절)의 `[engine]` / `[engine:live]` 줄에서 턴 종료 사유와 오류를 볼 수 있습니다.

## 11. 용어집

저장소 루트의 `glossary.json`에 제품/업계 용어를 언어별로 적습니다.

```json
{
  "terms": [
    { "ko": "적도의 마운트", "en": "equatorial mount", "ja": "赤道儀マウント", "zh": "赤道仪支架" }
  ]
}
```

- 항목마다 `ko`, `en`, `ja`, `zh`를 채웁니다. 빈 문자열은 무시됩니다.

**현재 상태: 용어집은 기본 엔진인 GPT-Live-1에만 적용됩니다.**

- **GPT-Live-1 (기본)**: 서버가 세션을 만들 때 공식 번역 프롬프트 뒤에 `Glossary: always render these source terms exactly as given.` 한 줄과 `원문 용어 => 번역 용어` 줄들을 붙여 `instructions` 필드로 보냅니다. 방향마다 그 방향의 원문/번역 언어 열만 씁니다. 줄은 최대 200개까지 넣습니다. 서버는 시작할 때 `glossary.json`을 한 번만 읽으므로, 파일을 고친 뒤에는 서버를 재시작하세요.
- **`gpt-realtime-translate`**: 적용되지 않습니다. 세션 설정에 용어집, 지시문(instructions), 키워드 힌트를 넣는 필드가 공식 문서에 없습니다([docs/api-notes.md](docs/api-notes.md) 1.6절, 4절). 고유명사나 전문 용어가 틀리게 번역될 수 있으니, 행사 전에 주요 용어를 직접 말해 보고 결과를 확인하세요.

## 12. 문제 해결

**마이크 권한을 거부했어요**
화면에 마이크 안내 배너가 뜹니다. 주소창의 자물쇠 아이콘(홈 화면 앱이면 크롬에서 같은 주소를 열어서) -> 권한 -> 마이크 -> 허용으로 바꾼 뒤 앱을 다시 엽니다. 안드로이드 설정 -> 앱 -> Chrome -> 권한 -> 마이크도 허용인지 확인하세요. HTTPS가 아닌 주소에서는 권한이 있어도 마이크가 안 됩니다.

**"재연결 중" 배너나 노란 점이 계속 보여요**
앱은 연결이 끊기면 1, 2, 4, 8, 15초 간격으로 다시 연결합니다. 계속되면 다음을 확인하세요.
- 폰 인터넷 연결, 그리고 Wi-Fi가 `api.openai.com`으로 가는 UDP를 막지 않는지 (6절). 모바일 데이터로 바꿔 보세요.
- Cloudflare Workers Logs에서 `/api/live/session`(GPT-Live-1) 또는 `/api/session`(gpt-realtime-translate) 응답이 502면 OpenAI 쪽 오류(키 잘못됨, 잔액 부족 등)입니다. 로그의 upstream 오류 줄에 원인이 나옵니다. 503이면 비밀값 `OPENAI_API_KEY` 또는 `APP_PIN`이 비어 있거나 형식이 틀렸습니다.

**PIN을 바꿨어요 / PIN 화면으로 돌아가고 싶어요**
Cloudflare 비밀값 `APP_PIN`을 바꾸면(즉시 적용), 이전 PIN을 기억하는 폰은 다음 접속 때 PIN 화면으로 돌아갑니다. 바로 초기화하려면 크롬에서 주소창 자물쇠 -> 사이트 설정 -> `데이터 삭제`(사이트 데이터 지우기)를 누르세요. 저장된 PIN, 설정, 대화 기록이 모두 지워집니다.

**"잠시 후 다시 시도해 주세요" (429)**
IP당 분당 요청 한도(약 30회)를 넘었습니다. 1분 기다리면 풀립니다. 여러 폰이 같은 부스 Wi-Fi(같은 공인 IP)를 쓰면 한도에 닿을 수 있습니다.

## 13. 알려진 제한 / 미확인 사항

공식 문서로 확인되지 않은 항목입니다([docs/api-notes.md](docs/api-notes.md)에서 **UNCONFIRMED** 표시). 운영에 영향이 있는 것만 적습니다.

- **WebRTC에서 `session.close` 동작**: 턴 끝에 남은 번역을 받아 내는 공식 방법은 `session.close`뿐인데, 문서는 WebSocket 기준으로만 설명합니다. WebRTC 데이터 채널에서 거부되면 앱은 "1.5초 동안 새 자막/음성이 없으면 턴 종료"로 대신 판단합니다(콘솔에 `[engine] session.close not accepted over WebRTC; using quiet detection`). 이 경우 말끝이 잘리거나 턴 종료가 조금 늦을 수 있습니다. 2026-10-16 실제 API 테스트(헤드리스 크롬, 6방향)에서는 모두 `session.closed`가 왔습니다. 중지 후 `session.closed`까지는 3.8~5.1초가 걸립니다. 그래서 앱은 끝까지 기다리지 않고 중지 즉시 버퍼를 재생하며 남은 음성을 이어 붙입니다(녹음이 끝난 뒤라 에코 없음).
- **기본 엔진의 한국어→일본어**: 실제 API 테스트에서 ko→ja 는 9회 중 6회 번역이 비어 있었고(오류 이벤트 없음, 세션의 출력 언어는 `ja`로 정상), 나머지도 일부는 잘리거나 엉뚱했습니다. 다른 5방향은 정상이었습니다. 빈 번역은 화면에 "번역 실패"로 표시됩니다. 같은 테스트에서 GPT-Live-1 엔진의 ko→ja 는 1회 정상이었습니다(반복 확인 필요).
- **유휴 연결 과금 (gpt-realtime-translate)**: 번역 중에는 빠른 응답을 위해 언어 방향별 연결을 미리 열어 둡니다(중지 상태에서는 연결이 없습니다). 가격은 오디오 시간 기준 분당 $0.034로 나와 있지만, 열어만 둔 연결 시간이 과금되는지는 문서에 없습니다. 행사 첫날 사용량 화면에서 확인하세요. GPT-Live-1은 연결 시간 기준 과금이 명시되어 있습니다(10절).
- **중국어 `zh` 코드의 의미**: 문서에는 없지만 실제 API 테스트에서 `zh` 출력은 간체 중국어였습니다.
- **WebRTC에서 번역 음성 이벤트 경로**: 문서상 번역 음성은 원격 오디오 트랙으로 오며, 앱도 그렇게 받습니다. 데이터 채널로도 음성 이벤트가 오는지는 미확인입니다(현재 앱 동작에는 영향 없음).
- **GPT-Live-1 엔진의 미확인 사항** (10절). 실제 API 테스트에서는 ko→en, en→ko, ko→ja, ko→zh 모두 번역되었고 모델이 대답하는 일은 없었으며, 중지 후 첫 음성까지 0.56~0.75초였습니다(방향당 1회씩만 시험):
  - **턴 경계**: Live 문서에는 사용자 턴 종료를 알리는 클라이언트 이벤트도, 번역 완료를 알리는 서버 이벤트도 없습니다. 앱은 출력이 멈춘 시간으로만 턴 종료를 판단하므로 말끝이 잘리거나, 다음 턴에 이전 번역의 끝부분이 섞여 나올 수 있습니다(턴 밖에서 온 출력은 버리고 콘솔에 `[engine:live] dropped` 줄을 남깁니다).
  - **언어 지원**: 문서에 지원 언어 목록이 없고 한국어, 일본어, 중국어 언급도 없습니다. 언어쌍마다 품질을 직접 확인하세요.
  - **mute 시 남은 번역 처리**: `session.input_audio.mute`는 모델에 무음을 보낸다고만 되어 있습니다. mute가 아직 나오지 않은 번역을 밀어내 주는지는 문서에 없어서, 버튼으로 끊은 구간의 번역이 끝까지 나오는지 보장되지 않습니다.
  - 그 밖에 Live용 브라우저 단기 토큰과 최대 세션 길이도 문서에 없습니다(만료 시각은 `session.started`에서 받은 값을 따릅니다).
